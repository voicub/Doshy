# Doshy

Isometric Home Assistant dashboard and home design tool (Next.js + react-three-fiber): draw your home and garden in 3D, link pieces to Home Assistant entities, and watch and control them live.

## Quick start

Needs Node.js 22.13 or newer (the database uses the built-in `node:sqlite`).

```
cp .env.example .env.local   # set HA_URL and HA_TOKEN (server-side only, never sent to the browser)
npm install
npm run dev                  # http://localhost:3000
npm run check                # typecheck + tests
```

Settings in `.env.local` (all read on the server; the full annotated list is `.env.example`):

| variable | |
|---|---|
| `HA_URL`, `HA_TOKEN` | Home Assistant address and a long-lived access token (required for live data) |
| `SKETCHFAB_TOKEN` | optional, enables downloading real 3D car models (see Cars) |
| `HOUSEY_AUTOMATION` | optional, `off` stops the curtains closing by themselves ([docs/curtains.md](docs/curtains.md)) |
| `HOUSEY_DB_PATH` | optional, database location (default `data/housey.db`) |
| `SITE_TILE_URL`, `SITE_TILE_MAX_ZOOM`, `SITE_TILE_CREDIT`, `HOUSEY_SITE_CACHE` | optional, satellite tiles and cache for Surroundings ([docs/site.md](docs/site.md)) |

Running it on a Raspberry Pi wall display or a phone: [docs/small-screens.md](docs/small-screens.md). More documentation: [docs/README.md](docs/README.md). Contributing: [CONTRIBUTING.md](CONTRIBUTING.md). Data credits: [CREDITS.md](CREDITS.md).

## Home Assistant

Install it from Home Assistant like a HACS repository. Both parts come from `https://github.com/voicub/Doshy`:

- **Add-on** (runs Doshy; Home Assistant OS or Supervised): **Settings > Add-ons > Add-on store > ⋮ > Repositories**, add the URL, install **Doshy**, start it, **Open Web UI**. No token needed.
- **Sidebar panel** (HACS integration): HACS > ⋮ > **Custom repositories**, the same URL, category **Integration**, download, restart, then **Add integration > Doshy**.

Details, Docker/Portainer, the https (mixed content) limit and what has been verified: [docs/home-assistant.md](docs/home-assistant.md).

## Docker

`docker compose up -d` (with `HA_URL` and `HA_TOKEN` in the environment or a `.env` file) pulls the image `ghcr.io/voicub/doshy` and runs it on port 3000; add `-f docker-compose.build.yml --build` to build it from this folder instead. Data (database, backups, imported models, map cache) lives in the `housey-data` volume at `/data`. In Portainer, deploy `docker-compose.yml` as a stack. The same image is the Home Assistant add-on.

## Features

- **Washing machines, dryers and dishwashers** with the [WashData](https://github.com/3dg1luk43/ha_washdata) integration: link an appliance with one tap, then see its state, progress and time left on it in the 3D home, in the room list and in a chip at the top, get a "done" toast, and pause, resume, mark unloaded or pick the program from its card. Details: [docs/washdata.md](docs/washdata.md).
- **Small screens** (a 7 inch Raspberry Pi wall display, or a phone): the compact layout is picked automatically. **Display** in the menu sets the layout, interface size, full screen, keep-screen-on and a screensaver; "Add to Home screen" installs it as an app. Setup guide for a Pi kiosk: [docs/small-screens.md](docs/small-screens.md).
- **Live** (default): isometric 3D garden and house at dusk. Click a lamp ring or a room chip to switch lights; lit lights glow with the colour and brightness Home Assistant reports. The sun icon cycles day / dusk / night; "Cut-away" lowers the walls.
- **Plan editor**: dock at the bottom has Wall, Room floor, Door, Window and the Furniture catalog (IKEA-style pieces, generic appliances, outdoor items, a custom box). Drag to move, `R` rotates, `Del` deletes, `Esc` cancels a tool. The inspector sets size, finish, entity link, floor type, wall surface (plaster or brick), and a room temperature sensor shown on the room chip.
- **Home Assistant**: states poll every 3 s via `/api/ha/states`; toggling goes through `/api/ha/toggle` (`homeassistant.toggle`).
- Your plan, settings and imported 3D models are stored in a small SQLite database on the machine that runs the dashboard (`data/housey.db`, see **Your data** below). The browser keeps a copy too, so the dashboard opens instantly and keeps working if the server is briefly unreachable. Export/Import JSON still works for sharing a single plan.
- **Vegetation** (Garden environment and the Outdoor catalog): trees, shrubs, hedges, grasses, flowers and rocks are built in code (`lib/vegetation.ts`, `lib/vegSpecies.ts`, `lib/vegBuilder.ts`): tapered branch tubes, noise-displaced clumps and alpha-tested leaf cards, no model files. One shader (`components/scene/foliageMaterial.ts`) colours them by season, sheds leaves in autumn, puts snow on up-facing surfaces and sways them with the live wind (direction, speed and gusts from `lib/wind.ts`; static lean only under reduced motion). Catalog items use `vegPart()` from `lib/catalog.vegetation.ts`.
- **Leaves, bark and houseplants** (scale with the Graphics quality tier, `lib/quality.ts` `foliage` and `grass` knobs): Light keeps the original big leaf clusters. Balanced, Detailed and Ultra build each tree, shrub and hedge from 2x, 4x and 7x as many smaller leaf cards, each carrying its own species' leaves (oak, maple, birch, linden, cherry, willow, spruce, pine ... painted procedurally into one shared 2048 px leaf atlas, `components/scene/foliageAtlas*.ts`), a visible twig structure (bare branches show in winter), rounder trunks with relief bark and light shining through leaves with the sun behind them (the denser tiers only, `uDetail` in the foliage shader); the lawn is drawn as fans of many thin tapered blades (`lib/vegGrass.ts`: upright blades in the middle, leaning ones arching out, darker roots and lighter tips, the season's grass colours, a few dead straw blades and seed heads, swaying with the live wind), thicker near the building and lighter far from it, and shrubs get a second leaf colour (rust in autumn). Houseplants and artificial plants (`lib/vegPlants.ts` and `lib/vegPlantFamilies*.ts`, catalog ids `pl_*` in `lib/catalog.plants.ts`, plus the upgraded `dc_plant_*` kinds) use the same leaf cards in an indoor material (always in leaf, never snowed on or blown by the outdoor wind). Browser-only limit: leaf cards are flat alpha-tested quads, so a crown reads as leafy and layered, not as every single leaf.
- **Garden lights, furniture and play** (Furniture catalog, "Garden", ids `gd_*`; `lib/catalog.garden.ts`, pieces in `lib/garden/`): LED bush lights (a real procedural shrub wrapped in twinkling bulbs, three sizes, warm white or colour-changing), tree wraps, hedge and rope lights, path lights and bollards, spot and uplights, deck / step / pond lights, festoon and fairy strings (3 to 12 m), lanterns, torches, a fire bowl, motion floodlight, neon signs and a smart controller box, plus dining sets, loungers, parasols, kitchens, hot tubs, swings, slides, climbing frames, a treehouse, statues, water features and planters. Link a light to a Home Assistant `light` or `switch` and every glow part follows on/off, brightness and RGB colour; the lights stay at or below 1.78 m so they never take the shadow slots of ceiling lamps. Swings, chimes, curtains, sails and baskets move with the live wind (`Def.wind`, `Part.spin.pivot`).
- **New plan** (Plan mode, dock): start any building from a template instead of the starter flat: blank apartment or house, studio flat, two-bedroom flat, or a two-storey family house with a garden. The current plan is replaced after a confirmation that offers to export it first (Undo also restores it). "Reset to starter" next to it brings back the original flat. Templates live in `lib/templates.ts`.
- **Surroundings** (Plan mode, globe button in the dock, or the command palette): draws the real neighbourhood around your home from public data: neighbouring buildings, trees, roads, water, real ground height and, if you turn it on, the satellite photo (found trees included). Off by default. The place is Home Assistant's home location, or coordinates you type or paste. In Plan mode the photo and the building outlines show faintly under your plan: press "Drag the map to line it up" and drag until the real building sits under your flat (or nudge with arrows, and turn the plan to face the right way). Every step can be undone and is saved with the plan (`plan.site`, optional). Only rounded coordinates leave your machine, through the server, to OpenStreetMap and Open-Meteo; the photo comes from a third-party tile service (Esri by default, `SITE_TILE_URL`) and only when its layer is on. Details: [docs/site.md](docs/site.md).
- **Floors, walls and colours** (Plan and Furniture modes, `B` or the paint bucket in the dock): 24 floors (oak, herringbone, marble, terrazzo, slate, deck, gravel, pool water ...) and 13 wall materials (red and white brick, concrete, wood cladding, stone, tile, wallpaper, board and batten, glass ...), each a procedural texture (`lib/textures.ts`, looks and defaults in `lib/materials.ts`) tinted by a named palette, recent colours or any colour. Pick a material and a colour once, then click walls, rooms or furniture; Alt-click picks a colour up, Shift-click paints both sides of a wall, a click on a room with a wall material paints all its walls, and "Paint all outside / inside walls" does the whole level. A wall has two faces (`Wall.style/color` = face A, the right-hand side walking a to b, `styleB/colorB` = face B, absent = same as A) so the outside can be brick and the inside sage plaster. Walls and rooms saved without these fields look exactly as before.
- **Stairs** (Furniture catalog, "Stairs"): straight (closed, open, wooden handrail, glass), L-shaped (turns left or right), U-shaped, winder, spiral, floating, loft ladder, basement stairs and entry / garden steps, each at the real step count for a 2.78 m storey (`lib/catalog.stairs.ts`). A stair is as tall as the level it climbs (`lib/voids.ts` `placedHeight`) and cuts its own opening in the floor above, which follows it when it is moved, turned or deleted (`withAutoVoids`, run on every plan edit so it shares the stair's undo step). **Stairs opening** (Plan mode, dock, key `7`) draws a hand-made hole in the active level's floor for any other case: drag a rectangle, resize by the corners, `R` turns it. Holes are real in 3D (floor and concrete slab); the lowest level lies on the ground and ignores them. Stored as `plan.voids`.
- **Entrance** (Plan mode, BUILDING dock button, Entrance, for apartments and houses): "Building hallway" opens the front door onto the building's shared corridor (a landing level with the flat, with neighbours' doors, lift, stairwell door, mailboxes and a fire extinguisher; the default for an apartment), "Door with stairs" generates the entrance steps or stairs when the floor is raised (the default for a house), "Door only" is just the door in the wall. The corridor is part of the building shell, not an item, so it never takes furniture or area, and it lowers with the walls in cut-away (`lib/hallway.ts`, `components/scene/BuildingHallway.tsx`; `Building.entry` is optional and the old value `street` still reads as `stairs`).

The `/api/ha/*` and `/api/db/*` routes are unauthenticated: run on a trusted network (home LAN, VPN) or behind a reverse proxy that signs people in, or add auth before exposing the app. The `/api/db/*` routes only accept same-origin requests, so another website cannot talk to them from your browser, but anyone who can reach the dashboard can read and change your plan.

## Your data

Everything you change is saved to `data/housey.db` (a SQLite file; Node's built-in `node:sqlite`, no extra install; set `HOUSEY_DB_PATH` to keep it elsewhere). `data/` is git-ignored. Back up that folder, or use **Data and backups** in the dock (or the command palette):

- **Plan versions**: while you edit, an automatic version of the plan is kept at most once every 5 minutes (the newest 30), and **Save version now** keeps a named one (newest 30). Restoring a version first keeps the plan it replaces, so a restore can be undone.
- **Files**: imported 3D models and your own pieces (25 MB per file, 500 MB in total; the same file imported twice is stored once).
- **Backups**: **Download backup** gives one `.db` file; **Import backup** checks it is a Doshy backup before replacing anything and keeps a safety copy first. The server also writes a daily copy to `data/backups/` and keeps the last 7.
- **First start with the database**: whatever the browser already had (plan, settings, custom pieces, 3D models) is copied into the database once, unchanged. The browser's copy stays as a fallback.
- **Two devices**: a plan saved on one device shows up on the other within about 15 seconds. If both have unsaved changes you are asked: **Load** the newer one or **Keep mine** (the other version stays in your saved versions).
- **Server down**: nothing is lost. Edits stay in the browser, the corner shows "Offline, will sync", and they are sent when the server is back.
- A damaged database file is moved aside as `housey.db.corrupt-<time>` and a fresh one starts, so the dashboard still opens.

Details for developers (tables, API, sync rules): [docs/database.md](docs/database.md). How the server talks to Home Assistant (caching, timeouts, background work) and deployment notes: [docs/server.md](docs/server.md).

## Materials and realism (Graphics quality)

Furniture parts are drawn with real materials, scaled by the Graphics quality tier (`lib/quality.ts`): **Light** is the original flat, sharp-edged look; **Balanced** adds rounded edges and colour/roughness textures; **Detailed** and **Ultra** add normal maps (grain, weave, pores), sheen on cloth and the small detail parts (handles, stitching, knobs).

- A catalog part may name a `tex` class (`wood`, `fabric`, `leather`, `metal`, `plastic`, `ceramic`, `stone`, `paint`, `rubber`, `foam`), `rough`, `metal`, a `bevel` radius, `shape: "lathe"` with a `lathe` profile, and `detail: 1 | 2` (shown only at tiers with that much detail). Without `tex` the class is guessed from the colour (`lib/materialsPbr.ts`). The part colour (and the owner's finish colour) stays the albedo: textures are greyscale multipliers.
- Textures are procedural and seamless (`lib/pbrTiles.ts`, drawn in time slices by `components/scene/pbr.ts` so no frame stalls; sizes 256/512/1024 by tier). `applyWorldUV` maps them in metres from the part's own axes, so grain and weave keep their real size on a resized or rotated piece and grain runs along the part's long side.
- Geometries and materials are cached and shared (`components/scene/partGeometry.ts`, `partMaterials.ts`); a tier change drops and rebuilds them. Glow parts keep their own material (their emissive is driven per piece).

The building shell follows the same tiers (`lib/shellLook.ts`, `lib/shellDetail.ts`, `components/scene/Wall*`, `RoomFloor`, `OpeningMesh`): **Light** keeps the flat voxel walls and floors; **Balanced** and up draw plaster, brick with mortar, concrete with formwork lines, wood boards, stone, wall tile and every floor (planks, tile grout, carpet, paving) as real textures whose size is metric (a brick course or plank is the same width on any wall or room); walls have flat ends and rounded top edges. From **Balanced** on there are also skirting boards, door and window casings (mitred), window sills with a drip groove, a base course on ground-floor walls, raised panels, handles and hinges on solid doors; **Detailed** adds crown moulding. Ends of walls that meet in a T or run on in a line stop at the junction so no two faces overlap.

## Busy rooms

A room with dozens of sensors and devices stays tappable. Every floating label in the 3D scene (lamp rings, sensor and plug badges, camera tags, room chips, Home Assistant link marks, energy labels) goes through one layer (`components/scene/DeclutterLayer.tsx`, layout maths in `lib/declutter.ts`, wall test in `lib/occlusion.ts`):

- Labels nudge out of each other's way and a thin leader line runs back to the device they belong to; they stay put while you orbit. Labels off screen, on a hidden storey or behind a wall (full-height walls) are not drawn; leaks, smoke, open doors and errors always are, on top.
- Calm sensors and idle plugs shrink to a small coloured dot until you zoom in, focus the room (double-click it, or pick it in the room list) or tap the dot. Lamps, switches, climate, media and cameras are always shown in full.
- Labels that still cannot be told apart fold into a numbered marker (`+7`). Tap it to fan the members out (a ring, or a list for wide ones) with 44 px targets; tap anywhere else or press Esc to fold them back.
- The **Declutter** switch in the top bar (Live and Home Assistant modes) turns all of this off: every label then sits exactly over its device.
- The small list button on a room chip, and **Devices** in the room list, open a sheet of every linked device in that room by type, with search, live values and a switch where one makes sense. Hovering or tapping a row pings the device in 3D; tapping its name moves the camera to it.
- **Picking and handles** (Furniture and Home Assistant modes; `lib/pickRank.ts`, `lib/gizmoPick.ts`, `components/scene/edit/`): every piece is picked by its biggest parts, not one big box, so the empty space under a table, between legs or in a shelf's cells is not a click target, and a click goes to what you see first. Tiny pieces get a 28 px (44 px on touch) click target that only counts where nothing real is under the pointer (or the tiny piece rests on what is). Thin poles and legs stay at least 12 px (22 on touch) wide. A rug loses to whatever stands on it, a container to what rests in it. Clicking the same spot again picks the next piece behind ("2 of 3"); Alt-click or a long press lists everything under the pointer; Tab / Shift+Tab step through the pieces under the pointer or in the room; Esc or a click on bare floor deselects. Pressing the selected piece always moves it, even when another piece ranks first. Hovering outlines what a click would select and names it with "+n behind". The ring and the arrow are drawn at a constant size on screen with a generous grab area (36 px, 48 on touch) and are tested before any piece; they light up when the pointer is on them ("Drag to turn" / "Drag to lift"). A small toolbar under the selection turns (-15, +15, 90), lowers and raises (5 cm, Shift 1 cm), picks another piece at that spot, locks, duplicates and deletes: the touch way, also reachable with the keyboard (Enter from the canvas, arrows, Esc). **Lock** (toolbar, dock, inspector) makes the pointer and the arrow keys skip a piece; it stays in the "Items in this room" list with a lock sign and can be selected there (`Item.locked`, optional, saved with the plan, undoable). **Pick through** (dock) makes a click select what lies behind the piece under the pointer. The inspector lists "Items in this room" with search.
- Dev builds expose the cost of the layout as `window.__declutter` (milliseconds per frame).

## Robot vacuum and cameras

- **Robot vacuum** (`ap_robot_vacuum`, with its `ap_robot_dock`): link it to a `vacuum.*` entity and in Live view it drives through its storey by the vacuum's state: docked (parked on the dock, green rim light), cleaning (zig-zag lanes room by room, a fading cleaned trail), returning (shortest way home), paused / error (stops where it is; error blinks red). Walls and floor furniture are obstacles (robot radius 0.17 m), rooms are joined only through doors, the path is deterministic for a given plan (`lib/vacuumPath.ts`, `lib/vacuumDrive.ts`). It drives at 0.25 m/s shown 6 times faster (`TIME_SCALE`) so a lap is watchable; with reduced motion it sits at a progress point. A vacuum that reports `x`/`y` or a `position` is followed instead (Home Assistant mode, Link panel: pick the unit it reports in, or shift it under Advanced); the device card says "Live position" or "Simulated path". Nothing here sends a command to the vacuum.
- **Cameras** (Furniture catalog, "Security": bullet, dome, indoor, video doorbell; plus alarm panel and keypad): link one to a `camera.*` entity. While furnishing, a cyan cone shows what it sees, stopped by walls but not by doors and windows; pick Wide / Normal / Narrow (angle and range under Advanced). In Live view the recording dot glows, and clicking a camera opens a card with a snapshot every 3 s (2 s enlarged), only while the card is open and the tab visible. Snapshots come through `GET /api/ha/camera?entity=camera.x`: read-only, one request per camera per 0.8 s and 120 per minute, image types only, 4 MB cap, `Cache-Control: no-store`, the Home Assistant token never leaves the server.

## Appliances and climate

The "Appliances" and "Climate" catalogue areas hold about 80 real-size devices: fridges (bottom-freezer, side-by-side, French door, under-counter, mini), freezer, ovens, ranges, hobs, hoods, dishwashers, microwaves, coffee machines, kettle, toaster, mixer, air fryer, wine fridges, washer, dryer, stacked tower, ironing board and drying rack; split and portable air conditioners, outdoor units and heat pump, fans, radiators, heaters, fireplace and wood burner, boilers, dehumidifier, humidifier, purifiers; robot vacuum and dock, stick vacuum, speakers, five TV sizes on the wall or on a low stand, soundbar, consoles, router, NAS, 3D printer, plug strip, chime and thermostats. Link one to a Home Assistant entity and it comes alive: displays and lamps glow, washer drums, fans and the mixer turn while the entity is on, the air-conditioner louvre swings, the fireplace lights the room orange. Wall-mounted pieces carry their mounting height, so a drop lands where it would hang. Defs live in `lib/catalog.appliances*.ts` (shared part helpers in `catalog.appliances-parts.ts`; `lib/appliances.test.ts` checks sizes, footprints and conventions).

## Sensors and smart plugs

The "Sensors" catalogue category has about 38 small devices at their real size (3-10 cm, each with a status LED): mmWave presence and PIR motion sensors, door / window contacts, water leak pucks, probes and ropes, flood sensor with valve, smoke, CO and gas detectors, vibration, temperature / humidity, light level, UV, air quality, noise, soil moisture, rain gauge, weather station, power plug, DIN energy meter, current clamp, smart lock, siren, buttons, bed pad, mailbox and fridge door sensors. Link one to a `binary_sensor`, `sensor`, `lock` or `siren` entity (HA mode) and it shows a badge with the reading in the state's colour (`lib/sensors.ts` classifies device classes and units: leak and smoke red, door open amber, temperature cool blue to warm orange, CO2 / air quality green to red, UV index bands, lux brightness). Presence and motion draw calm radar rings, alarms pulse a halo, a leak drips, an open door blinks, vibration shakes; reduced motion keeps colour and a static ring only. With the walls lowered, wall and ceiling sensors keep their badge at the wall-top height.

**Make it smart with a plug** (HA mode, select an appliance): a basic washer, dryer, dishwasher, kettle, coffee machine, TV, printer or dehumidifier on a smart plug runs "by the watts". Pick the plug (suggested by name and room) and its power sensor is found by entity-id (`switch.washing_machine` finds `sensor.washing_machine_power`); a slider sets "Running above X W" with the live reading marked on it, and Test only reads. `lib/running.ts` turns the power draw into off / standby / running / finished with per-appliance defaults, hysteresis, a minimum start time and pause tolerance, using the last three hours of `/api/ha/history` plus the live readings (without history it still answers from the live watts). A running appliance spins its drum or fan, glows (dryer warm, dishwasher blue pulse, TV flicker) and steams (kettle, coffee machine), with a badge such as "Washing, 412 W / Running 0:42" or "Finished / 3 min ago". The settings are stored in the item's `params` (`plugEntity`, `powerEntity`, `runAbove`). Sensors placed in a room are not summed into the room chip: the chip still reads the room's own linked fields.

## Cars

The catalogue ("Garage & EV", filter by body type) has 180+ cars at their real size: hatchbacks, sedans, estates, SUVs, crossovers, coupes, convertibles, pickups, vans, minivans, microcars and sports cars, petrol, diesel, hybrid and electric. Place one, pick a paint colour from the swatch row (24 factory-style colours plus a free picker) and rotate it like any other piece. Electric cars have a closed grille and a charge flap, the others a grille and an exhaust tip.

- Link a car to a `device_tracker.*` or `person.*` entity: it stands solid (headlights lit) while the tracker says `home` and turns into a faint ghost with an "away" tag on `not_home`. A car linked to any other sensor shows nothing special.
- The 3D is procedural bodywork, not boxes: a lofted shell from the model's real length, width, height and wheelbase with wheel arches cut into it, a glasshouse with window frames, shut lines, door handles, mirrors, roof rails, headlights with a daytime-running strip, grille, fog lights, wrapping tail lights, exhaust tips or a charge flap, and real wheels (tyre, 5 to 10 spoke rim, brake disc and caliper). Per-model design (grille, lamps, wheels, roofline) comes from `lib/cars.design.ts`; the body-style defaults and the loft are in `lib/carFrame.ts` / `lib/carGeometry.ts`. Each car is a handful of merged meshes (6k to 12k triangles, a decimated variant when zoomed far out) with clear-coated paint that reflects the scene; no extra lights. No brand logos are drawn.
- Paint: 24 factory colours plus a free picker, and a Gloss / Metallic / Matte finish (`params.finish`).
- Number plate: type your own plate in the inspector (A-Z, 0-9, space, hyphen, up to 10 characters) and pick EU, Romania, UK (yellow rear), US, Plain or Blank. It appears on the front and rear bumpers at the real plate size; blank until you type one (`params.plate`, `params.plateStyle`).

### Real 3D models (optional): "Make this car look exact"

The procedural cars are generic shapes. For a real one, open a car in the inspector and press **Make this car look exact**: the finder searches [Sketchfab](https://sketchfab.com) (pre-filled with e.g. "Mitsubishi ASX 2016", with regional names such as "Outlander Sport" offered as alternatives), shows thumbnails with licence badges and triangle counts, and **Use this model** downloads, simplifies and fits it. Every car of that catalogue model then shows the real model (the catalogue gets a "Real model" badge); **Back to the built-in model** undoes it, and a model that is missing on a device (cleared storage, another computer) simply draws as the built-in car, because plans only store the catalogue car id.

- **Automatic (the easy way)**: **Use a real model (automatic)** in the car inspector (or in the finder) lets the server pick the best Sketchfab model for that catalogue car (`lib/modelRank.ts`: brand and model words in the name and tags, regional names such as Outlander Sport, the generation or year, a sensible triangle count, popularity as a tie-break; concepts, wrecks, toys, wheels and other brands are rejected; scans rank lower because they cannot be recoloured) and does the whole import for you. **Not right? Try the next one** moves on to the next-best model. **Upgrade all cars in my plan** (inspector and catalog drawer) does this for every car kind in the plan, one after another in the background with a result line per car. **Fetch a real model automatically when I place a car** (off by default, remembered) does it for newly placed cars. In the finder you can also paste a Sketchfab link or model id to use exactly that model.
- **Without a token** the app shows a 3-step card (get the token, copy the `.env.local` line, "I added it, check again") instead of an error; `GET /api/models/status` answers `{tokenConfigured}` only. `POST /api/models/auto {carId, skip?}` is the automatic route (same safety checks as the import route, 12 per minute).
- **Enable downloads** (searching works without it): create a free Sketchfab account, copy your API token from `sketchfab.com/settings/password`, add `SKETCHFAB_TOKEN=your-token` to `.env.local` (next to `HA_URL`; server side only, never sent to the browser), and restart `npm run dev`.
- **Licensing, why no models are in this repository**: third-party models are never bundled. Each user fetches the models they want with their own Sketchfab account and token, as Sketchfab's [Download API guidelines](https://sketchfab.com/developers/download-api/guidelines) require. Only models under **CC0, CC BY or CC BY-SA** are offered (search is filtered on the server and every result is re-checked); NonCommercial, NoDerivatives, "Standard" and editorial licences, paid and non-downloadable models are never shown. The author, licence, source link and a ready-made attribution line are saved with every model and listed under **Credits** (catalog drawer, "3D model credits", and the car inspector); the licences require that credit to stay visible wherever the model is used, so keep it when you share pictures. Models are provided by Sketchfab. The app never re-publishes a model.
- **Server routes** (`app/api/models/*`, code in `lib/modelLibrary.ts`): `GET /api/models/search?q=&cursor=&heavy=1` (compact list, up to 200 000 triangles, 1 000 000 with "Allow heavy models") and `POST /api/models/import {uid}` (token only on the server; only `api.sketchfab.com` and the signed download host it returns, over https; 60 MB, 60 s and zip-bomb limits; the file is checked as a real GLB with no external links, cameras, lights, animations or extras are removed; rate limited). Errors are plain-language JSON, e.g. `needs_token` with the setup steps.
- **In the browser** (`lib/carOptimise.ts`): hidden parts (engine, seats, ground planes, tiny parts) are dropped, meshes merged per material, vertices welded and the result simplified with three's meshoptimizer-based `SimplifyModifier` to about 60 000 triangles near and 8 000 far (the far one shows when zoomed out), textures above 2048 px are shrunk. A model with a million triangles takes a few seconds. The optimised `.glb` is kept through `lib/modelStore.ts`; the description (`lib/carModelStore.ts`, `lib/carModels.ts`) holds the fitting.
- **Fitting**: the model is turned so its length runs along the car and its nose points to the front arrow (a guess from the roof position; **Rotate 90°** and **Flip front / back** fix it), put on the ground by its lowest wheel (**Move up / down**, **Fix ground**), and scaled to the catalogue's published length x width x height (mirrors do not count). A model whose shape is more than 6 % off gets "This looks like a different generation" and keeps its own proportions at the right length.
- **Paint**: the biggest non-glass, non-chrome, non-rubber material (or the one named paint / body / carpaint) takes the paint colour and finish with a clear coat; **Which part is the paint?** lets you pick another material, **Keep the model's original colour** leaves it alone. Glass stays glass, lamps glow when the linked tracker says home, and the model's own number-plate mesh (found by name) shows your plate.

### Add your car

Add one line to `lib/cars.data.ts` and open a pull request:

```ts
["Mitsubishi", "ASX 2016", "crossover", "petrol", 4.295, 1.77, 1.625, 2.67, "Silver"],
//  brand       model      body         fuel      length width height wheelbase paint   [, extra]
```

Body is one of `hatchback sedan estate suv crossover coupe convertible pickup van minivan microcar sports`; fuel is `petrol diesel hybrid ev`. Sizes are metres from the maker's data sheet (width without mirrors). Paint is a name from `CAR_COLORS` in `lib/cars.ts` or a `#hex`. An optional last object tunes the shape when the body style default looks wrong, e.g. `{ roof: "fastback", wheels: "multi", port: "l" }` (all options are listed at the top of `lib/cars.data.ts`). `npm test` checks that every row has sensible dimensions, a valid colour, no duplicate id, and a charge flap on EVs only.
